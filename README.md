# 그림 이어말하기

**서비스 주소: https://timage.labbitory.com**

교실에서 쓰는 온라인 그림 전달 파티 게임입니다. 학생들은 **제시어 → 그림 → 추측 → 그림 → 추측** 순서로 내용을 전달하고, 마지막에 방장이 보여 주는 화면을 **다 함께** 보며 어디서 이야기가 바뀌었는지 웃습니다.

- 교사가 클래스를 만들고 학생을 확인하며, 학생 중 **방장 자격**을 줄 사람을 직접 고릅니다.
- 교사 또는 방장 자격 학생만 게임방을 만들고, 학생들은 클래스 로비에서 원하는 방에 들어갑니다 (방마다 4~12명).
- 방장은 함께 플레이하거나 **참관하며 진행**할 수 있고, 참관 방장·교사는 참가자의 그림·추측 초안을 실시간으로 봅니다.
- 결과 공개는 **방장 한 명이 넘기는 화면을 전원이 동일하게** 봅니다. 학생은 이전/다음, 다른 그림책, 전체 결과를 따로 열 수 없습니다. 이 규칙은 UI 와 서버 양쪽에서 지켜집니다.
- 점수·순위·승패·AI 판정은 없습니다.

기술 구성: React 19 + TypeScript + Vite 8, Tailwind CSS 4, HTML Canvas 2D + Pointer Events, Cloudflare Workers (Static Assets + HTTP API + WebSocket), SQLite 기반 Durable Objects 3종 (WebSocket Hibernation API, Alarm), Vitest, Playwright.

## 1. 설치와 로컬 실행

요구 사항: Node.js 22 이상 (개발은 24.16 에서 확인), npm.

```bash
npm install
cp .dev.vars.example .dev.vars   # Windows PowerShell: Copy-Item .dev.vars.example .dev.vars
```

`.dev.vars` 의 `TEACHER_ACCOUNTS` 에 실제 비밀번호 해시를 넣습니다 (2절). 그 다음:

```bash
npm run dev
```

http://localhost:5173 이 열립니다. Vite 개발 서버 안에서 Cloudflare Vite 플러그인이 Worker 와 Durable Objects 를 **로컬(workerd)** 로 실행하므로 Cloudflare 계정 없이도 전체 기능이 동작합니다. 로컬 Durable Object 데이터는 `.wrangler/state/` 에 저장됩니다.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 (프런트 + Worker + DO 로컬) |
| `npm run typecheck` | 클라이언트·워커·테스트 타입 검사 (`tsc -b`) |
| `npm test` | Vitest 단위 테스트 (배정 알고리즘, 검증, 해시, 제시어) |
| `npm run test:e2e` | Playwright E2E (dev 서버를 자동으로 띄움) |
| `npm run build` | 타입 검사 후 프로덕션 빌드 (`dist/`) |
| `npm run deploy` / `npm run deploy:staging` | Wrangler 로 수동 배포 (10절) |
| `npm run hash-password -- "비밀번호"` | 교사 비밀번호 해시 생성 |

## 2. 초기 교사 계정 준비

공개 회원 가입은 없습니다. 운영자가 서버 비밀 변수 `TEACHER_ACCOUNTS` 에 교사 계정을 넣습니다.

1. 해시 생성 (PBKDF2-SHA256, 100,000회, 16바이트 무작위 salt):

   ```bash
   npm run hash-password -- "선생님이-쓸-비밀번호"
   ```

   출력 예: `pbkdf2-sha256$100000$…salt…$…hash…`

   > 반복 횟수 100,000 은 Cloudflare Workers 의 WebCrypto 상한입니다. 더 큰 값으로 만든 해시는 로컬에서는 통과하지만 배포 후 로그인이 실패합니다.

2. JSON 배열로 만듭니다. `id` 는 클래스 소유권 식별에 쓰이므로 나중에 바꾸지 마세요.

   ```json
   [
     {"id":"t-kim","username":"kim","name":"김선생","passwordHash":"pbkdf2-sha256$100000$…"},
     {"id":"t-lee","username":"lee","name":"이선생","passwordHash":"pbkdf2-sha256$100000$…"}
   ]
   ```

3. 로컬: `.dev.vars` 의 `TEACHER_ACCOUNTS=` 뒤에 한 줄로 넣습니다. 운영: `wrangler secret put TEACHER_ACCOUNTS` (11절).

비밀번호 검증은 서버(DirectoryObject)에서만 이루어지며, 평문 비밀번호나 해시는 클라이언트 번들에 포함되지 않습니다. 로그인 실패는 IP·아이디별 10분에 8회로 제한되고, 세션은 12시간 뒤 만료되며 로그아웃 시 즉시 삭제됩니다. 계정을 `TEACHER_ACCOUNTS` 에서 제거하면 기존 세션도 무효가 됩니다.

## 3. 교사 로그인 → 클래스 생성 → 학생 참여 → 방장 지정

1. `/teacher` 에서 로그인합니다.
2. 클래스 이름을 입력해 **만들기**. 6자리 입장 코드(0/O, 1/I 같은 혼동 문자 제외)가 생성됩니다.
3. **QR · 초대 링크** 버튼으로 QR 코드와 `/join/<코드>` 링크를 보여 줍니다.
4. 학생은 홈에서 코드와 닉네임(2~12자)만 입력합니다. 회원 가입·이메일 없음. 같은 닉네임은 `닉네임(2)` 처럼 번호로 구분됩니다. 서버가 추측 불가능한 세션 토큰을 발급하고, 새로고침·재접속 시 같은 학생으로 복원됩니다.
5. 교사 화면의 학생 목록은 새로고침 없이 실시간으로 늘어나며 접속 상태·방장 자격·현재 방·플레이/참관 여부를 보여 줍니다.
6. 학생 행의 **방장 지정**을 누르면 그 학생에게 방장 자격이 생깁니다. **방장 해제**로 회수하면 새 방 생성과 진행 권한이 즉시 사라지고, 운영 중이던 방은 교사가 진행권을 인수하거나 다른 방장을 지정할 때까지 "방장 없음" 상태가 됩니다 (게임 데이터는 유지).
7. **입장 잠그기**로 신규 참여를 막을 수 있고, **내보내기**로 학생을 클래스에서 제거할 수 있습니다.

## 4. 방 생성 → 학생 자유 입장 → 준비 → 시작

- 교사 대시보드 또는 방장 자격 학생의 로비에서 **방 만들기**: 제목(2~30자), 플레이 정원(4~12, 기본 12), 방장 모드(참관/참여), 제시어 방식(후보 3개 / 직접 입력), 그리기 60/90/120초, 추측 30/45/60초.
- 교사는 자신이 참관 방장이 되거나, 방장 자격이 있고 다른 방에 없는 학생을 방장으로 지정할 수 있습니다.
- 학생 로비에는 같은 클래스의 방만 카드로 보입니다: **참여하기** / **가득 참** / **게임 진행 중**.
- 한 학생은 동시에 한 방에만 속합니다. 대기실에서 나가면 다른 방에 들어갈 수 있고, 진행 중인 방에는 새로 들어갈 수 없습니다 (기존 참가자의 재접속은 허용).
- 대기실에서 플레이어는 **준비 완료!** 를 누릅니다. 방장이 설정을 바꾸면 준비 상태가 초기화됩니다.
- 시작 조건: 실제 플레이어 4~12명, 전원 접속·준비. 정원을 다 채우지 않아도 시작할 수 있습니다. 시작하면 플레이어 순서가 고정됩니다.

## 5. 참여 방장과 참관 방장의 차이

| | 함께 참여 | 참관하며 진행 |
|---|---|---|
| 플레이어 수 포함 | ✅ (정원 소모) | ❌ (12명 + 방장 = 13번째 연결 가능) |
| 제시어·그림·추측 작성 | ✅ | ❌ |
| 다른 사람 초안 실시간 모니터링 | ❌ (자기 작업만 봄) | ✅ |
| 게임 시작·결과 공개 진행 | ✅ | ✅ |

방장 모드는 대기실에서만 바꿀 수 있습니다. 진행 중에 참관으로 바꿔 정답을 엿본 뒤 다시 플레이하는 일은 서버가 막습니다. 교사가 직접 플레이하는 경우도 플레이어 수에 포함되고 모니터링은 할 수 없습니다.

## 6. 교사 모니터링과 진행권 인수

- 교사 대시보드에서 모든 방의 상태·인원·방장을 한눈에 봅니다 (전체 현황 먼저).
- **방 방문·모니터링**을 누르면 그 방에 참관자로 연결되어 플레이어별 카드(닉네임, 작업 종류, 접속·제출 여부, 그리는 중인 그림/입력 중인 추측, 마지막 갱신 시각)를 실시간으로 봅니다. 카드를 누르면 확대와 직전 입력 확인. 실제로 연 방의 초안만 구독합니다.
- 학생 화면에는 "선생님 참관 중" 또는 "방장 참관 중"이 표시됩니다.
- **진행권 인수**: 방장이 끊겼거나 자격을 회수했을 때 교사가 진행권을 가져와 게임 시작·결과 공개를 진행합니다. **방장 교체**: 그 방에 있는 방장 자격 학생에게 넘깁니다. 새 방장이 현재 플레이어면 이번 판은 플레이어로 남고 모니터링 권한은 없습니다. 이전 방장이 복귀해도 권한은 자동 복원되지 않습니다.
- 방장이 끊겨도 타이머와 제출은 계속되고, 새 게임 시작·공개 진행만 멈춥니다.
- **강제 종료**: 교사는 확인 후 진행 중인 방을 닫을 수 있습니다.

## 7. 방장의 공동 결과 공개

1. 모든 단계가 끝나면 방은 `REVEAL_READY` 가 되고 학생에게는 "방장이 결과 공개를 준비하고 있어요"가 보입니다.
2. 방장이 **결과 공개 시작**을 누릅니다.
3. 방장 화면 오른쪽 **참가자** 목록(그림책 소유자 기준)에서 한 명을 누르면 그 그림책이 모두의 화면에 표지로 나타납니다.
4. **다음 →** 으로 제시어 → 그림 → 추측 → … 을 한 장씩 공개합니다. **← 이전**도 됩니다. 참가자 목록에는 미공개/진행 중(n/m)/완료가 표시됩니다.
5. 학생 화면은 방장이 고른 같은 참가자·같은 항목만 보여 주고, 방장이 넘기면 자동으로 바뀝니다. 학생에게는 이전/다음 버튼, 썸네일, 다른 책 선택, 전체 목록, 저장·내보내기가 없습니다. **확대**는 현재 항목만 가능하고, 확대 중에 방장이 넘기면 확대 화면도 함께 바뀝니다. 반응 버튼(ㅋㅋ·놀람·최고)은 1.5초에 한 번 보낼 수 있습니다.
6. 서버는 `gameId · bookId · entryIndex · revealRevision` 으로 공개 상태를 관리하고 모든 학생에게 같은 상태를 방송합니다. 학생 스냅샷에는 현재 항목 하나만 담기며, 아직 공개하지 않은 항목이나 전체 그림책은 전송되지 않습니다. 오래된 revision 의 명령은 거부되고, 재접속하면 최신 화면으로 복원됩니다. 연결이 끊긴 동안에는 "최신 화면인지 확인할 수 없어요" 안내가 뜹니다.
7. 모든 그림책의 모든 항목이 최소 한 번 공개되면 서버가 `FINISHED` 로 바꿉니다. 도중에 다른 책으로 넘어간 것은 완료로 치지 않습니다. 전체 공개 전에는 다시 시작·방 닫기가 안 되며(교사 강제 종료만 가능), `FINISHED` 뒤에도 학생 독립 탐색은 없습니다.

네트워크 지연을 없앤 "절대 동시" 표시를 보장하지는 않습니다. 모든 화면이 같은 서버 상태로 신속히 수렴하도록 만들었습니다.

## 8. 다시 시작과 방 닫기

- **다시 시작**: 대기실로 돌아가고 남아 있는 참가자를 유지하되 준비 상태를 초기화합니다. 빈자리에 새 참가자가 들어올 수 있고, 다음 시작 때 4~12명을 다시 확정하며 새 `gameId` 와 새 배정이 만들어집니다. 이전 판의 초안·제출·공개 명령은 무효입니다. 이전 판 데이터는 삭제됩니다.
- **방 닫기**: 확인 후 `CLOSED`. 모두에게 안내 후 소켓이 종료되고 학생은 클래스 로비로 돌아갑니다. 클래스의 방 목록과 학생의 현재 방 소속이 해제되며, 닫힌 방 링크·늦은 요청은 거부됩니다. 30초 뒤 저장 데이터가 삭제됩니다.
- **클래스 종료**(교사): 소속 방을 모두 종료(실패 시 재시도 큐)하고 학생 세션을 해제한 뒤 데이터가 삭제됩니다.

`.gitignore` 가 `.dev.vars`, `.wrangler/`, `dist/`, `node_modules/`, 테스트 결과를 제외합니다. **`.dev.vars` 와 비밀번호 해시가 담긴 파일은 절대 커밋하지 마세요.** `.github/workflows/ci.yml` 이 push 마다 타입 검사·단위 테스트·빌드를 실행합니다 (배포는 하지 않음).

## 10. Cloudflare Workers GitHub 연결과 빌드·배포

Workers Builds 를 쓰면 GitHub push 로 자동 배포됩니다.

1. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Import a repository** → GitHub 연결 후 이 저장소 선택.
2. 빌드 설정:
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy` (production 브랜치 `main`)
   - Root directory: `/`
   - Node 버전: 22 이상 (`NODE_VERSION` 환경 변수 또는 `.nvmrc`)
3. 첫 배포 전에 11절의 비밀(`TEACHER_ACCOUNTS`)과 `ALLOWED_ORIGINS` 값을 설정합니다.
4. 배포 후 `wrangler.jsonc` 의 `ALLOWED_ORIGINS` 를 실제 주소로 바꾸고 다시 push 합니다. 커스텀 도메인을 쓴다면 `routes` 에 `{ "pattern": "<도메인>", "custom_domain": true }` 를 함께 적습니다.

수동 배포: `npx wrangler login` 후 `npm run deploy`.

**미리보기(Preview) 제약**: Cloudflare 문서에 따르면 Durable Object 를 구현한 Worker 에는 버전 미리보기 URL 이 생성되지 않습니다. 따라서 PR 미리보기 대신 12절처럼 별도 staging Worker(환경)를 두고 검증합니다. Workers Builds 의 비프로덕션 브랜치 빌드도 production 설정을 쓰지 않으므로, staging 브랜치의 Deploy command 를 `npx wrangler deploy --env staging` 으로 따로 지정하세요.

**현재 배포 상태(2026-09-22):** production 에 배포 완료.

| 항목 | 값 |
|---|---|
| 주소 | https://timage.labbitory.com (커스텀 도메인) |
| Worker 이름 | `picture-relay` |

## 11. 인증 비밀과 바인딩 설정

`wrangler.jsonc` 에 이미 다음이 설정되어 있습니다.

- Durable Objects 바인딩: `DIRECTORY`(DirectoryObject), `CLASSES`(ClassObject), `ROOMS`(RoomObject)
- 마이그레이션 `v1`: `new_sqlite_classes` 로 세 클래스를 SQLite 기반으로 등록 (무료 요금제에서도 동작)
- 정적 자산: `assets.not_found_handling = single-page-application`, `run_worker_first = ["/api/*", "/ws/*"]`
- `compatibility_flags: ["nodejs_compat"]`, `observability.enabled = true`

비밀·변수:

```bash
# production
npx wrangler secret put TEACHER_ACCOUNTS        # 2절의 JSON 한 줄을 붙여넣기
# staging
npx wrangler secret put TEACHER_ACCOUNTS --env staging
```

`ALLOWED_ORIGINS` 는 비밀이 아니므로 `wrangler.jsonc` 의 `vars` 에 적습니다. Worker 는 요청 자기 자신의 origin 도 허용하므로 기본 workers.dev 주소는 별도 설정 없이 동작하지만, 커스텀 도메인·다른 origin 에서 API 를 부르려면 목록에 추가해야 합니다. `ENVIRONMENT` 는 production 이 기본이며, `production` 이 아닐 때만 테스트용 `x-forwarded-for` 헤더로 IP 를 흉내낼 수 있습니다 (운영에서는 절대 `development` 로 두지 마세요).

## 12. staging/production 및 저장소 분리

`wrangler.jsonc` 의 `env.staging` 은 이름이 `picture-relay-staging` 인 별도 Worker 로 배포되며, Durable Object 네임스페이스도 Worker 별로 분리되므로 **staging 과 production 의 클래스·방 데이터는 서로 섞이지 않습니다.** 마이그레이션은 환경별로 상속되지 않고 최상위 설정이 공통 적용됩니다.

```bash
npm run deploy:staging     # staging 에 배포
npm run deploy             # production 에 배포
```

로컬 개발 데이터(`.wrangler/state/`)는 둘 다와 별개입니다.

## 14. 사용량·비용·로그 확인

- Cloudflare 대시보드 → Workers & Pages → 해당 Worker → **Metrics**(요청·오류·CPU), **Logs**(observability 활성화됨, `wrangler tail` 로도 실시간 확인).
- Durable Objects 사용량: **Durable Objects** 메뉴에서 요청 수·저장 용량·활성 시간. 이 앱은 방당 한 객체, 클래스당 한 객체, 디렉터리 한 객체를 씁니다. 매초 방송을 보내지 않고 알람 기반이라 대기 중 비용이 낮습니다.

## 15. 데이터 보관과 삭제

- 영구 학생 프로필이나 장기 앨범은 없습니다. 이메일·생년월일을 받지 않습니다.
- 클래스와 게임 데이터는 **마지막 유효 활동으로부터 24시간** 뒤 Durable Object 알람이 자동으로 삭제합니다. heartbeat(ping)·모니터링 수신은 유효 활동으로 치지 않습니다. 방이 활발히 진행 중이면 그 방의 최근 활동 시각이 클래스 만료 판단에 반영됩니다.
- 방 닫기 후 30초, 클래스 종료 후 통지 큐가 비면 즉시 삭제됩니다. 종료 후 접근은 곧바로 차단됩니다.
- 삭제 대상: 그림·초안·항목·학생 명단·세션 토큰·방장 자격·입장 예약·요약. 교사 계정 설정(`TEACHER_ACCOUNTS`)은 임시 수업 데이터와 분리되어 영향받지 않습니다.
- 브라우저 `localStorage` 에는 학생 세션 토큰과 미제출 초안이 남을 수 있습니다. 로비의 "이 기기에서 클래스 나가기"로 지울 수 있습니다.
- 보관 정책은 홈·로비·대시보드 화면에도 표시됩니다.

## 16. 코드 되돌리기와 스키마 호환성

- 배포 되돌리기: 대시보드 **Deployments** 에서 이전 버전으로 롤백하거나 `npx wrangler rollback`.
- Durable Object 저장 스키마는 각 객체 생성자에서 `CREATE TABLE IF NOT EXISTS` 로 만들고, 메타는 KV 키(`meta`/`room`) 하나에 JSON 으로 둡니다. 새 필드를 추가할 때는 읽는 쪽에서 기본값을 처리해야 이전 데이터와 호환됩니다.
- 이전 코드로 롤백하면 새 코드가 만든 데이터는 무시되거나 기본값으로 읽힙니다. 데이터는 24시간 안에 사라지므로, 스키마가 크게 바뀌는 배포는 **수업이 없는 시간에** 하고 필요하면 클래스를 종료한 뒤 배포하세요.
- DO 클래스 이름을 바꾸거나 삭제하려면 `migrations` 에 `renamed_classes` / `deleted_classes` 항목을 추가해야 합니다 (Cloudflare 문서 참조). 기존 마이그레이션 태그는 수정하지 마세요.

## 17. 구조·명세 문서

```
shared/        타입 · 프로토콜 · 배정 알고리즘 · 검증 (서버·클라이언트 공용)
worker/        Worker 진입점 · lib(인증·HTTP·빈도 제한·제시어) · do/(Directory · Class · Room)
src/           React 앱 · canvas/(그림판) · pages/ · components/
tests/unit     Vitest       tests/e2e  Playwright + Node WebSocket 하네스
docs/PERMISSIONS.md   권한 표
docs/PROTOCOL.md      API/WebSocket 메시지 · 상태 머신 · 데이터 모델
docs/IMAGES.md        일러스트 3장이 들어가는 화면과 생성용 프롬프트
```

Durable Object 역할:

- **DirectoryObject**(단일): 교사 로그인·세션, 로그인 실패 제한, 클래스 코드 색인.
- **ClassObject**(클래스별): 학생 명단·토큰·방장 자격, 방 목록 요약, 입장 예약(예약 → 방 입장 → 확정, 실패·예외 시 알람으로 대조·복구), 방으로 보내는 통지 재시도 큐.
- **RoomObject**(방별): 명단·설정·상태 머신, 그림책·항목·초안(SQLite), 실시간 모니터링 중계, 공동 공개 위치, 단계 기한·만료 알람.

배정 규칙(명세 8절)은 `shared/assignment.ts` 에 있으며 4~12명 전부에 대해 중복·누락·단계 수·마지막 추측을 단위 테스트로 검증합니다.

**배포에서만 드러난 문제 (수정 완료):** Cloudflare Workers 의 WebCrypto 는 PBKDF2 반복 횟수를 10만 회까지만 허용합니다(`iteration counts above 100000 are not supported`). 처음에는 21만 회를 썼는데 로컬 workerd 는 이 제한을 적용하지 않아 로컬 테스트 전부가 통과했고, 배포 후 교사 로그인만 500 으로 실패했습니다. 상한을 10만으로 낮추고, 한도를 넘는 해시는 500 대신 인증 실패로 처리하면서 운영자용 경고 로그를 남기도록 고쳤습니다. 회귀를 막는 단위 테스트를 추가했습니다.

**로컬 개발 환경에서 관찰한 주의점:** Vite 개발 서버를 거치는 로컬 WebSocket 은 클라이언트가 메시지를 한 번도 보내지 않은 소켓에 서버 쪽 종료 프레임이 전달되지 않았습니다. 클라이언트는 연결 직후 `ping` 을 보내므로 실제 앱에는 영향이 없지만, 직접 프로토콜 클라이언트를 만들 때는 참고하세요.

## 19. 명세에 없어 결정한 사항

- 학생 세션은 `localStorage` 에 클래스별로 저장하고, WebSocket 은 쿼리 파라미터 `token` 으로, HTTP 는 `Authorization: Bearer` 로 보냅니다 (교사만 쿠키). 학생이 여러 클래스에 동시에 참여할 수 있게 하기 위해서입니다.
- 교사가 만든 방의 교사 방장은 방 명단에 "선생님" 구성원으로 표시됩니다. 참관 모드면 플레이어 후보에서 제외됩니다.
- 방장 자격을 회수당한 참관 방장은 방에 남아 있지만 플레이어도 참관자도 아닌 대기 상태가 되며, 다음 판(다시 시작 후)에는 일반 플레이어 후보가 됩니다.
- 직접 입력 제시어 모드에서 시간 내 입력하지 않으면 서버 제시어 목록에서 무작위로 정합니다.
- 제출 후 남은 시간 동안은 "제출했어요" 화면에서 기다립니다. 마지막 사람이 제출하면 서버가 바로 다음 단계로 넘깁니다.
- 반응(ㅋㅋ·놀람·최고)은 저장하지 않고 연결된 모두에게 즉시 흘려보냅니다.
- 그림 저장 상한: 획 600개, 획당 400점, 전체 30,000점, 250KB. 색 12개·굵기 3단계 외의 값은 서버가 거부합니다.
- 제출은 한 번 누르면 바로 반영되고 확인 창을 띄우지 않습니다. 되돌릴 수 없다는 안내는 버튼 옆에 미리 적어 두었습니다. 전체 지우기처럼 실수로 많은 것을 잃는 조작만 확인을 받습니다.
- 결과 공개에서 제시어·추측도 그림과 같은 4:3 칸에 담습니다. 칸 높이가 항목마다 달라지면 아래의 이전/다음 버튼이 오르내려 누르기 어렵습니다.
- 일러스트 3장(`public/images/`)은 모두 선택 사항입니다. 파일이 없거나 로딩에 실패하면 그 자리만 비고 레이아웃은 그대로입니다.
  - 첫 화면(학생 참여·교사 로그인)은 컴퓨터·태블릿에서 왼쪽 입력창 + 오른쪽 친구들 그림으로 두고, 휴대폰에서는 그림을 뺍니다.
  - 양옆 낙서 배경은 로그인한 뒤부터(교사 대시보드·클래스 화면·학생 로비·게임방 대기실) 나오고, 게임이 시작되면 작업에 집중하도록 뺍니다.
  - 노트 마스코트는 클래스가 없을 때, 열린 방이 없을 때, 게임방에서 기다릴 때 나옵니다.
  - 자세한 배치는 docs/IMAGES.md 에 적혀 있습니다.
- 접근성: 버튼 이름·키보드 포커스·reduced-motion 을 지원하지만, 캔버스에 직접 그리는 입력 자체는 스크린 리더로 대체할 수 없습니다. 추측·제시어 단계는 키보드만으로 가능합니다.
