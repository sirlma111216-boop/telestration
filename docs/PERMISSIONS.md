# 권한 표

역할은 하나의 문자열이 아니라 세 가지 축으로 표현된다.

| 축 | 값 | 어디에 저장 |
|---|---|---|
| 신원 | 교사 / 학생 | 교사: HttpOnly 세션 쿠키(DirectoryObject) · 학생: 클래스별 세션 토큰(ClassObject, SHA-256 해시 보관) |
| 방장 자격(HostGrant) | 있음 / 없음 | ClassObject `members.host_grant` — 교사만 부여·회수 |
| 현재 방장(진행권) | 방마다 `host.userId` 한 명 (없을 수도 있음) | RoomObject `host` |
| 플레이어 여부 | 이번 판 `game.players` 포함 여부 | RoomObject `game.players` (판 시작 시 고정) |

모니터링 권한 = (교사 본인 ∨ 현재 방장) ∧ 이번 판 플레이어가 아님 ∧ (학생 방장이면 참관 모드).
조작(진행권) = 현재 방장 ∧ 주 연결(가장 최근 탭).

## 권한 변화 시 즉시 적용되는 것

- 방장 자격 회수 → 그 학생이 운영하던 방의 진행권이 비고(`host.userId = null`), 열린 WebSocket 의 `canControl`/`canMonitor` 가 다음 스냅샷에서 false 가 된다. 게임 데이터는 유지된다.
- 교사 진행권 인수 / 방장 교체 → 이전 방장의 명령은 즉시 거부된다. 이전 방장이 다시 접속해도 권한은 복원되지 않는다.
- 클래스 내보내기 → 학생 토큰 무효화, 클래스·방 소켓 종료, 방 명단에서 제거(진행 중이면 건너뜀 처리).
- 중복 탭 → 가장 최근 연결만 조작 가능. 이전 탭은 보기 전용.
